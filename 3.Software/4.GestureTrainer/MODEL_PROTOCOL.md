# 独立手势模型协议 v1

`.wandmodel` 不包含固件、功能编号或灯效。整数与浮点数使用小端序。

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 8 | ASCII MWMODEL1 |
| 8 | 4 | 协议版本1 |
| 12 | 4 | 类别数2～16（当前电脑产品8～16） |
| 16 | 4 | TFLite字节数，最多49152 |
| 20 | 4 | 输入特征协议1 |
| 24 | 16 | mean[2]、std[2]，float32；std有限且大于0 |
| 40 | 1024 | 16个UTF-8名称槽，每个64字节、以NUL结束 |
| 1064 | 24 | 保留，写0 |
| 1088 | 可变 | INT8 TFLite模型 |
| 末尾 | 32 | 前面全部字节的SHA256 |

特征协议1：输入 `[1,100,2]` INT8，沿用魔杖双轴预处理，先按包内mean/std归一化，再按张量scale/zero point量化并饱和。输出 `[1,N]` INT8，对应包内名称顺序。基础固件使用50KiB张量区，上传前必须实际分配并试运行。

正常设备模式下 GET `/api/model` 查询协议、容量、当前模型包哈希及更新状态。POST同一路径发送原始包，头 `X-Wand-Model: 1`。202只表示接收，返回ticket；客户端轮询，重启后active_hash等于目标包SHA256才确认生效。内置模型也按相同格式计算哈希。

模型存储占用原128KiB spiffs数据分区的两个64KiB槽，不格式化文件系统，不改分区表。只写非活动槽，载荷回读后最后写提交标记；启动时验证最新槽，失败尝试上一槽，再回退内置模型。更新期间暂停设备动作。固件维护入口仅允许应用更新，禁止文件系统上传覆盖模型区。

SHA256提供完整性校验，不是身份签名。设备保持原本的本地Wi-Fi信任边界。协议、输入特征或算子支持改变时，需要相应升级基础固件。
